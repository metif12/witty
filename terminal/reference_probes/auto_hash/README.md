Run `run.py ZIG V REPOSITORY` with Zig 0.15.2 and the repository's pinned V compiler. It compiles Zig's unchanged `std.hash_map.AutoContext`, verifies fifteen native results against the V regression fixture, runs the actual caller-backed generic map test, and checks both compilers' rejection of floating point, direct slices, nested slices, and an inactive union branch containing a slice. Pointer and function addresses are compared to their numeric addresses within a process; their values are not compared across ASLR processes.

The translated generic map retains the original Robin Hood probing, metadata, offset relocation, capacity rules, adapted contexts, pointer access, and callbacks. V key/value types supply their actual storage size and alignment. Source declarations with a specified integer or enum backing type must retain that backing type in V, or use the ABI factory's concrete integer aliases.

V cannot store an unhandled `!T` result as a first-class key. `SourceHashResult[T]` supplies the source error-union's selected error or payload. V's `IError` bridge hashes and compares only `code()`, which must be a nonzero source `u16` error ID; it never hashes messages or interface storage. The source native fixture uses `@errorFromInt(1)` to verify that exact numeric identity. The compiler's unused optional `err` field is never visited by a real optional hash.

V 0.5.2 forbids concrete `?T` generic type arguments, strips optional flags from nested generic context arguments, and rejects arithmetic on a pointer to an optional generic key. A direct inferred optional value can be hashed, but an optional alias cannot be used as a map key. `source_hash_optional(?T)` and `auto_offset_optional_hash_map_inferred(...)` provide an executable ordinary-struct boundary: no-value and payload equality and hashing match the source, including shallow nested slices. For nullable pointer payloads, hashing emits the zero or present pointer's numeric address. This explicit value adapter has V's struct layout; it is not a claim of Zig optional ABI compatibility. Untagged unions and SIMD vectors have no direct V value counterpart and require an explicitly generated representation/custom context, just as source untagged unions require an explicit context.

The original `hasUniqueRepresentation` branch is retained over V's actual storage: integers, enums, pointers, function pointers, fixed arrays of unique elements, and structs whose unique fields fill the complete object use raw bytes. Nonunique structs visit declared fields and exclude padding. Zig automatic struct field reordering has no implicit V counterpart: use source-compatible generated/native field layout when comparing raw ABI hashes. Zig packed logical bit counts and comptime fields are unavailable to V reflection; a C packed or opaque declaration must expose its source hash through an explicit context when those details are hidden. No layout is guessed from a matching name.
